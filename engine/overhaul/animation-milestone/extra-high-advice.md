## Decisions requiring Extra High attention

1. **Define acceptance before authoring thousands more routines.** Distinguish a reusable motor primitive, an authored object sequence, an actor/context variant, and an execution of that sequence. A family library with 48 entries does not establish 48 sequences for each item. A palette, duration, label, random seed, generic reaction or isolated helper attachment must not add a sequence count. Reuse implementation freely; require an explicit object binding, appropriate construction/material contacts, a purposeful physical progression and reviewable evidence for each accepted sequence. Do not impose global uniqueness across all 29,232 obligations: the user's requirement is a meaningful bespoke repertoire for each object, not 29,232 unrelated human activities.

2. **Resolve authoritative movement and contact once, then reuse the contract.** Castle care currently validates native Cheese against `queue_a` (`engine/carnival.py:123`) while `castleGeometry` moves the displayed body among controls (`engine/client/castle-care.mjs:28`). The native station function advances from elapsed time; it does not establish that a body path between those controls is reachable. The renderer also constructs a line from wing to target without a reach bound. This is a concrete split between native occupancy and displayed occupancy, not evidence that any particular screenshot looks wrong. Decide whether native activity state owns the articulated root path or a shared, deterministic geometry artifact supplies both native occupancy/contact checks and rendering. Gates, collisions, weather exposure, interruption and conversation must use the same physical location. Do not require a rewrite of every renderer before the first pilot; establish this contract on the pilot and migrate affected controllers incrementally.

3. **Make participant and resource reservation a common invariant.** `LivingPond._activity` calls many family controllers; `MindGarden.tick` and company modules repeat long exclusion lists. This increases the chance that each new family forgets one competitor, release path or pause condition. Define one activity owner per actor, per-copy reservations, tool/material reservations, visit-token validity and idempotent completion. Add a narrow registry/adapter interface around existing controllers; retain their useful mechanics. Guest-to-guest object use and species-appropriate helper roles need this decision before more Cheese-only companion modules proliferate.

4. **Solve the genuinely different domains explicitly.** `LivingPond.available()` rejects eggs (`engine/living_world.py:417`); the item path rejects food and wearables (`:512`). More normal item scores cannot close these holes. Egg participation needs truthful observation/caregiver scenes without an egg walking or wearing clothing. Consumable actions must wrap the original quantity-changing handlers with exactly-once contacts and cancellation rules. Wearables need ownership-preserving dressing, removal, storage and visitor/shared-care participation. Held tools need real pickup, transport, use and return. Effects/auras, flight attachments, water/ice support and oversized mechanisms require dedicated semantics, not copied cloth/idle loops. Keep these designs with Extra High; give Medium implementation only after the contract is concrete.

5. **Separate semantic distinctness from structural uniqueness.** The castle test fingerprints `[station, track, effects]` (`engine/tests/castle-care.test.mjs:8`); another value or effect can make a signature unique without establishing a new performance. The visitor geometry test proves useful fitting properties, not personality-specific acting. The native castle cast loop assigns one score per cast member (`engine/check_castle_work.py`, the `enumerate(PROFILES)` loop), rather than every score to every visitor. Preserve these tests, but describe their actual coverage. None is a per-object repertoire certificate.

## Concrete defects and scaling traps to address

- **Premature shared-learning credit:** `MindGarden._encounter` bonds, learns, restores social state and records a past interaction before `encounters.create` succeeds (`engine/mind_garden.py:412–422`). Completion later learns again (`:521–525`). An invitation can fail or be interrupted after the first credit. Define separate invitation/conversation/completed-activity events, then move each reward to its demonstrated event. A bounded Medium fix can follow that decision, with failed creation, failed arrival, cancellation and one successful completion checked explicitly.
- **Portable companion anchor mismatch:** `portable_ground.OFFSET` is `7*132/192` native cells (`engine/portable_ground.py:10`), and the renderer uses `plan.portable.object`. Keepsake, creative, textile and ground company modules still construct the prop center as `origin.x + 7` native cells. Their intended center is therefore displaced by 2.1875 native cells. Derive it from the saved portable point; validate the companion stance against terrain/obstacles rather than only rectangular screen bounds. This is a suitable bounded Medium task after the active drawing integrations.
- **Selector expansion can silently strand authored work:** `playdates.choose` selects the first option unequal to the last (`engine/playdates.py:41`). There are currently two scores per family, so this is not an existing third-score failure; adding a third makes it unreachable under ordinary unchanged conditions. Other selectors intentionally prioritize specific contexts. Require an eligibility witness and an actual production-selection path for every new sequence, including explicitly player-selected sequences. Do not test reachability by directly overwriting a running plan's ID.
- **Ice is not interchangeable with water:** the new footwear gate uses `water_at`; ordinary water and load-bearing frozen support are not yet distinguished, according to the parent implementation report. Decide the support model before spreading snow/ice choreography. Keep “may stand here,” “may swim here,” and “is protected by a roof” as separate physical facts, with actual weather/material state and arrival.

## Executable path to verified repertoires

**First, establish a small evidence index, not a second simulation.** Add proposed `repertoires/<object>.json` records and a reusable audit runner. Each sequence record needs a stable ID; purpose; object construction/anchors; ordered actor roles and contact/mechanical events; native controller entry point; original-state prerequisites; completion effects; cancellation/save policy; contextual eligibility; age/species adaptations; and evidence references. Track candidate, implemented, replayed, reviewed and verified separately. An entry with missing evidence stays a candidate. Bind IDs to actual production commands/controllers, including the original inventory/wardrobe paths.

Each accepted object-sequence requires:

1. A native scenario starting from legitimate disposable fixture state, through production selection/request, independent arrival, activity and exit. Record per-copy identity, actor/visit identities, support, contact events, state deltas and completion tokens. An observation can have no material delta; it must still have a purposeful object-specific performance.
2. Rendered evidence from those native frames at approach, meaningful anticipation, each contact/mechanical transition, reaction and exit. Static catalogue sheets and manually fabricated scene fixtures remain useful subordinate checks.
3. A semantic distinction review within that object's repertoire. Normalize away labels, palette, seed and duration when clustering contact/pose traces; inspect nearest matches together. Hashes detect literal duplicates and cache unchanged work; they cannot certify meaning. Multi-step procedures can count when their task, coordination and physical progression are substantive. Arbitrary concatenations or reordering of identical chores cannot fill the remaining slots.
4. Eligibility and participation evidence for all requested ages, visitors and contexts. Declare the actual anatomy-appropriate role; a refusal alone is not the promised participation. An egg may observe a visitor's action; a butterfly need not acquire hands. Check actual season/time/weather/need/mood/relationship selection and transitions, not merely labels. Run every required binding, shard native runs and reuse unchanged evidence by source/dependency hashes. Quick representative checks may speed development; they do not replace the final requested exhaustive audit.
5. Targeted interruption evidence before contact, after irreversible contact, while a partner arrives, on lost ownership/placement, travel, urgent care, weather change and save/reload. Already-applied physical effects persist, completion rewards remain single-use and reservations release. Shared lifecycle tests can serve many scores where the same controller truly owns the behavior; object-specific contact/resource exceptions still need their own cases.

Compute `verifiedSequences` from accepted, current evidence. Do not manually increment it after a drawing or a new core. Changes to a shared rig/controller/anchor invalidate dependent evidence; an unrelated drawing should not invalidate everything. Keep a visible list of unresolved actor/context bindings so a score's partial progress cannot masquerade as full object completion.
